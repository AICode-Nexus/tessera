# v0.6 Subagent Runtime Ownership Design Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Design the persistent sub-agent scheduler/runtime ownership path over existing v0.6 session metadata without implementing child execution yet.

**Architecture:** Keep `core` as the only runtime owner and keep `protocol` as provider-neutral metadata. The first slice records a strict runtime contract for parent/child lifecycle, transcript artifact lifecycle, approval forwarding, inactive-child handling, cancellation and reattach boundaries. Execution remains gated until these contracts are reviewed, replayable and projected.

**Tech Stack:** Rust workspace docs, Markdown architecture contracts, `tessera-protocol`, `tessera-core`, `tessera-client`, `tessera-storage`, `tessera-gui-bindings`, `cargo fmt`, `cargo clippy`, `cargo test`, `git diff --check`.

---

## Scope

Implement only design and planning updates in this slice:

- A written runtime ownership contract for persistent sub-agent scheduling.
- Version/global plan updates that mark the next implementation order.
- Crate boundary updates that keep scheduler ownership in `core`.
- Protocol/trace design notes for future runtime-only events.
- A staged implementation plan with TDD checkpoints and explicit forbidden behavior.

Do not implement in this slice:

- Real child-agent execution.
- Concurrent fan-out.
- Swarm scheduling.
- Tool execution, shell/file/git execution, apply-patch, or workspace mutation.
- Automatic approval forwarding.
- App-server listener, daemon, hook runtime, automation runtime, MCP runtime, or provider socket freezing.
- GUI Git mutation or checkpoint restore/revert.

## Design Decisions

- `SubagentRuntimeCoordinator` will live in `tessera-core`, not CLI/TUI/GUI/client.
- Child sessions reuse existing task lifecycle concepts and must emit existing `Task*`, `TaskOwner*`, `SubagentSession*`, `AgentHandoff*`, and `ReviewerGate*` events before any UI can observe them.
- The scheduler is bounded: no unbounded recursion, no hidden fan-out, no child session without `SubagentSessionCaps`.
- Transcript artifacts are handles first. Child transcript storage must be artifact-backed and replayable before parent context can reference summaries.
- Approval forwarding is policy-mediated. Session metadata may carry forwarding links, but runtime forwarding requires explicit events and reviewer/policy gate checks.
- Inactive child handling must be deterministic: pause parent, queue decision, or require reviewer. Silent continuation is forbidden.
- Cancellation and reattach must use task ownership metadata; no provider socket freezing is introduced in v0.6.
