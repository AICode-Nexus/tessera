# v0.5 Background Task Ownership v1 Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Tessera's first trace-backed background task ownership foundation with execution owner leases, heartbeat metadata, lost-owner projection, and explicit reattach outcomes.

**Architecture:** Add provider-neutral ownership metadata to `tessera-protocol`, reconstruct owner state in `tessera-core::RuntimeReader`, then add a core-owned recorder/helper and read-only CLI/client projection. This does not add a daemon, listener, provider socket freezing, tool execution, workspace mutation, or non-chat resume.

**Tech Stack:** Rust, `tessera-protocol`, `tessera-core`, `tessera-client`, `tessera-cli`, JSONL trace, cargo contract tests, `git diff --check`.

---

## Scope

Implement only:

- `RuntimeInstanceId`, `ClientInstanceId`, and `TaskOwnershipId`.
- Trace-safe ownership metadata for execution leases, heartbeats, detach/lost state, and reattach outcomes.
- `RunEvent` variants for task ownership and reattach metadata.
- `RuntimeReader` projection for current ownership status from JSONL records.
- A small core helper for appending ownership metadata through `TraceStore`.
- No-tool chat / agent run attach and detach metadata if the helper is small enough for this slice.
- Read-only CLI/client projection of owner status.
- Documentation updates.

Do not implement:

- A background daemon.
- HTTP/app-server listener.
- Provider socket freezing.
- Tool execution.
- MCP runtime.
- Hook or automation runtime.
- Workspace restore/revert.
- Non-chat task resume.
- Subagent persistence.
- Swarm scheduler.

Implementation outline:

```rust
pub fn list_task_owners(&self, trace_id: &str) -> Result<Vec<RuntimeTaskOwnerSummary>> {
    let records = self.store.read_trace_records(trace_id)?;
    let mut owners = Vec::new();
    let mut task_statuses = Vec::new();
    for record in &records {
        apply_task_record(&mut task_statuses, record);
        apply_task_owner_record(&mut owners, record)?;
    }
    apply_terminal_task_status_to_owners(&mut owners, &task_statuses);
    Ok(owners)
}
```

- [ ] **Step 5: Implement projection helper**

Rules:

- `task_owner_attached` inserts or replaces by `lease_id`.
- `task_owner_heartbeat` updates status, `last_heartbeat_at`, `expires_at`, and `last_seq`.
- `task_owner_detached` sets status `Detached`.
- `task_owner_lost` sets status `Lost`.
- terminal task statuses force `TerminalProjection` reattach mode.
- paused tasks with checkpoint remain `ResumeFromCheckpoint` if a checkpoint exists in later task.
- heartbeat/attached execution owner remains `ObserveExistingOwner`.
