# v0.6 Persistent Subagent Session Foundation Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Design and implement the first persistent sub-agent session foundation on top of existing v0.6 handoff/reviewer events, without adding swarm scheduling, tool execution, file mutation, or background fan-out.

**Architecture:** Extend Tessera's provider-neutral protocol and trace model with child-session metadata, parent/child task linkage, transcript artifact handles, session caps, approval forwarding policy, and inactive-child handling. Keep runtime ownership in core, JSONL as event truth, and `tessera-client` / GUI bindings as read-only projections. This slice records and projects sub-agent session state only; it does not spawn concurrent workers, execute tools, call provider SDKs from UI, or let child sessions mutate files.

**Tech Stack:** Rust, `serde`, `ts-rs`, `tessera-protocol`, `tessera-client`, `tessera-gui-bindings`, Markdown docs, `cargo fmt`, `cargo clippy`, `cargo test`, `git diff --check`.

---

## Scope

Implement only:

- A written v0.6 persistent sub-agent session contract.
- Provider-neutral protocol DTOs/events for:
  - parent/child task linkage;
  - sub-agent session metadata;
  - transcript artifact handles;
  - per-session caps for steps, recursion depth, concurrency slot, timeout and cost;
  - approval forwarding metadata;
  - inactive-child handling metadata.
- Read-only client projection and GUI bindings for these metadata events if implementation proceeds after the design commit.
- Roadmap and architecture updates that keep v0.7 coding-agent mutation blocked until reviewer/checkpoint/policy gates exist.

Do not implement:

- Real persistent child-agent runtime scheduling.
- Background fan-out, parallel sub-agent execution, swarm scheduler, or planner/worker orchestration.
- Tool execution, shell/file/git execution, apply-patch, or workspace mutation.
- MCP runtime, hook runtime, automation runtime, daemon/app-server listener, or provider socket freezing.
- Default/global instruction loading, executable skills, skill install/update/delete, or Claude import expansion.
- Real checkpoint restore/revert or GUI Git mutation.

    pub memory_scope_labels: Vec<String>,

}
