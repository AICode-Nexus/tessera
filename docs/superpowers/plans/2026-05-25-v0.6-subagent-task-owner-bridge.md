# v0.6 Subagent Task Owner Bridge Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add non-executing core helpers that bridge sub-agent session metadata to existing task owner attach/detach metadata.

**Architecture:** Reuse existing `TaskOwnerLease` and `RunEvent::TaskOwnerAttached` / `TaskOwnerDetached` shapes. Extend `SubagentRuntimeCoordinator` with request types, validation, a lease builder, and event helpers while keeping scheduler, provider execution, storage writes, tools, UI, heartbeat loops, lost-owner detection, and reattach execution out of scope.

**Tech Stack:** Rust, `tessera-core`, `tessera-protocol`, Markdown docs, `cargo fmt`, `cargo clippy`, `cargo test`, `git diff --check`.

---

## Scope

Implement only:

- `SubagentTaskOwnerAttachRequest`.
- `SubagentTaskOwnerDetachRequest`.
- Core validation and event helpers for existing task owner protocol records.
- Targeted core tests.
- Roadmap/docs/changelog status updates.

Do not implement:

- Child-agent scheduling or provider execution.
- Automatic task owner persistence.
- Heartbeat loops.
- Lost-owner detection.
- Provider socket freezing.
- Automatic reattach.
- Automatic approval forwarding.
- Inactive-child execution.
- Storage writes from the helper.
- Tool execution.
- GUI commands.
- Hooks, automations, MCP runtime, app-server listener, swarm, workspace mutation, memory, or learning runtime.

- attach requires a child task id;
- active execution owner attach targets the child task id and preserves trace/runtime/client metadata;
- observer owner attach is allowed for waiting/inactive metadata-only sessions;

- terminal sessions cannot attach a new owner;
- detach event targets the child task id and preserves lease id and reason;
- attach events are metadata-only.


Expected: FAIL before implementation because request types and helper methods do not exist.

- [x] **Step 2: Implement request types and helpers**

Add:

```rust
pub struct SubagentTaskOwnerAttachRequest {
    pub session: SubagentSessionDescriptor,
    pub trace_id: String,
    pub runtime_id: RuntimeInstanceId,
    pub client_id: Option<ClientInstanceId>,
    pub owner_kind: TaskOwnerKind,
    pub last_seq: Option<u64>,
    pub heartbeat_interval_ms: u64,
    pub reason: String,
}

pub struct SubagentTaskOwnerDetachRequest {
    pub session: SubagentSessionDescriptor,
    pub lease_id: TaskOwnershipId,
    pub reason: Option<String>,
}
```

Add methods on `SubagentRuntimeCoordinator`:

- `task_owner_lease(request) -> Result<TaskOwnerLease, SubagentRuntimeError>`
- `task_owner_attach_event(request) -> Result<RunEvent, SubagentRuntimeError>`
- `task_owner_detach_event(request) -> Result<RunEvent, SubagentRuntimeError>`

Validation:

- attach requires `child_task_id`.
- attach requires non-empty `trace_id`, non-empty `reason`, and `heartbeat_interval_ms > 0`.
- execution owner attach requires active session status.
- observer owner attach is allowed for planned, active, waiting-for-approval, inactive and handed-off session statuses.
- completed, failed and cancelled session statuses cannot attach a new owner.
- detach requires `child_task_id`.
