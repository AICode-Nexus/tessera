# v0.6 Subagent Owner Heartbeat Bridge Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add non-executing core helpers that bridge sub-agent child task metadata to existing task owner heartbeat, lost-owner, and reattach events.

**Architecture:** Reuse existing protocol event shapes. Extend `SubagentRuntimeCoordinator` with request types and validation that return `RunEvent` values only, leaving storage writes, heartbeat loops, lost-owner detection, automatic reattach, provider execution, tools, workspace mutation, and UI actions out of scope.

**Tech Stack:** Rust, `tessera-core`, `tessera-protocol`, Markdown docs, `cargo fmt`, `cargo clippy`, `cargo test`, `git diff --check`.

---

## Scope

Implement only:

- `SubagentTaskOwnerHeartbeatRequest`.
- `SubagentTaskOwnerLostRequest`.
- `SubagentTaskOwnerReattachRequest`.
- Core validation and event helpers for existing task owner heartbeat/lost/reattach protocol events.
- Targeted core tests.
- Roadmap/docs/changelog status updates.

Do not implement:

- Heartbeat loops.
- Lost-owner detection.
- Automatic reattach.
- Provider resume or provider socket freezing.
- Child-agent scheduling or provider execution.
- Storage writes from the helper.
- Tool execution.
- GUI commands.
- Hooks, automations, MCP runtime, app-server listener, swarm, workspace mutation, memory, or learning runtime.

- [x] **Step 2: Implement request types and helpers**

Add:

```rust
pub struct SubagentTaskOwnerHeartbeatRequest { ... }
pub struct SubagentTaskOwnerLostRequest { ... }
pub struct SubagentTaskOwnerReattachRequest { ... }
```

Add methods on `SubagentRuntimeCoordinator`:

- `task_owner_heartbeat_event(request) -> Result<RunEvent, SubagentRuntimeError>`
- `task_owner_lost_event(request) -> Result<RunEvent, SubagentRuntimeError>`
- `task_owner_reattach_event(request) -> Result<RunEvent, SubagentRuntimeError>`

Validation:

- all helpers require `child_task_id`;
- heartbeat rejects completed/failed/cancelled sub-agent sessions;
- lost-owner and reattach require non-empty reason;
- `ObserveExistingOwner` reattach requires `new_lease_id`;
- `ResumeFromCheckpoint` reattach requires `checkpoint_id`;
- `OwnerLost` reattach requires `previous_lease_id`;
- `TerminalProjection` is projection-only metadata and allowed without checkpoint/new lease.
