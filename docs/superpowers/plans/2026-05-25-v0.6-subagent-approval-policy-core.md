# v0.6 Subagent Approval Policy Core Helper Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add non-executing core helpers for sub-agent approval-forwarding and inactive-child policy records.

**Architecture:** Reuse existing protocol DTOs and events. Extend `SubagentRuntimeCoordinator` with deterministic request types, validation, record builders, and event helpers while keeping execution, scheduling, storage writes, provider calls, tools, and UI out of scope.

**Tech Stack:** Rust, `tessera-core`, `tessera-protocol`, Markdown docs, `cargo fmt`, `cargo clippy`, `cargo test`, `git diff --check`.

---

## Scope

Implement only:

- `SubagentApprovalForwardingRequest`.
- `SubagentInactivePolicyRequest`.
- Core validation and event helpers for existing approval-forwarding and inactive-policy protocol records.
- Targeted core tests.
- Roadmap/docs/changelog status updates.

Do not implement:

- Automatic approval forwarding.
- Child-agent scheduling or execution.
- Provider calls.
- Tool execution.
- Storage writes from the helper.
- GUI commands.
- Hooks, automations, MCP runtime, app-server listener, swarm, workspace mutation, or transcript body storage.

- [ ] **Step 1: Write failing core tests**

Add tests proving:

- queued approval forwarding requires a reviewer gate;
- forwarded-to-parent records preserve approval id and reviewer gate metadata;
- forwarded-to-parent rejects a session already marked as forwarded from parent;
- denied-by-policy events are metadata-only;
- inactive require-reviewer policy emits an event with reviewer-oriented parent action;
- mismatched inactive policy and parent action are rejected deterministically.

Run:

```bash

```

Expected: FAIL before implementation because request types and helper methods do not exist.

- [ ] **Step 2: Implement request types and helpers**

Add:

```rust
pub struct SubagentApprovalForwardingRequest {
    pub session: SubagentSessionDescriptor,
    pub approval_id: ApprovalId,
    pub reviewer_gate_id: Option<ReviewerGateId>,
    pub status: SubagentApprovalForwardingStatus,
    pub reason: String,
}

pub struct SubagentInactivePolicyRequest {
    pub session: SubagentSessionDescriptor,
    pub policy: SubagentInactivePolicy,
    pub parent_action: SubagentInactiveParentAction,
    pub reason: String,
}
```

Add methods on `SubagentRuntimeCoordinator`:

- `record_approval_forwarding(request) -> Result<SubagentApprovalForwardingRecord, SubagentRuntimeError>`
- `approval_forwarding_event(request) -> Result<RunEvent, SubagentRuntimeError>`
- `record_inactive_policy(request) -> Result<SubagentInactivePolicyRecord, SubagentRuntimeError>`
- `inactive_policy_event(request) -> Result<RunEvent, SubagentRuntimeError>`

Validation:

- `QueuedForReviewer` requires `reviewer_gate_id`.
- `ForwardedToParent` rejects `session.approval_forwarding.forwarded_from_parent == true`.
- `ForwardedToParent` requires the provided `approval_id`.
- `DeniedByPolicy` allows missing reviewer gate.
- `RequireReviewer` inactive policy allows `RequireReviewer` or `PauseParent`.
- `QueueDecision` inactive policy requires `QueueDecision`.
- `PauseParent` inactive policy requires `PauseParent`.

Update `crates/core/src/lib.rs` to export the new request types.
