# v0.7 Automatic Isolated Worktree Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in automatic isolated worktree lifecycle for trace-driven apply-patch so `tessera apply-patch --from-trace --auto-worktree` can prepare a safe detached worktree before reusing the existing apply-patch gate/executor.

**Architecture:** Keep lifecycle semantics core-owned and trace-backed. Add provider-neutral worktree lifecycle metadata, a non-destructive planner, an injectable Git worktree runner for the small allowed Git operation set, and CLI wiring that remains valid only for trace-driven apply. The slice may create/remove a detached isolated worktree created by the current invocation, but it must not stage, commit, push, run tests, restore checkpoints, switch the primary checkout or expose GUI/TUI/app-server mutation controls.

**Tech Stack:** Rust workspace (`protocol`, `core`, `cli`, `client` if projection is added), JSONL trace events, `TraceStore`, Clap, tempdir contract tests, injected command runner tests, Markdown docs.
