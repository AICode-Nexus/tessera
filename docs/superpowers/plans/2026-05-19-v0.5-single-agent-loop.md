# v0.5 Single Agent Loop Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Tessera's first no-tool single-agent runtime loop with trace-backed task/step events and a script-friendly CLI entrypoint.

**Architecture:** Add small protocol metadata for agent run and step summaries, then add a `tessera-core` `AgentLoop<P>` that follows the existing `ConversationEngine` provider/storage/event-sink pattern. CLI gets a non-interactive `tessera agent run` command that returns text or JSON; TUI/GUI remain projection-only clients.

**Tech Stack:** Rust, `tessera-protocol`, `tessera-core`, `tessera-cli`, `tessera-client` projection only if needed, JSONL trace, SQLite index, cargo contract tests.

---

## Scope

Implement only:

- no-tool single-agent run.
- one provider step by default.
- `TaskKind::AgentRun`.
- agent run/step trace events.
- machine-readable run summary.
- cancellation, pause, provider failure, and no-progress finish paths.
- CLI `tessera agent run --provider <id> --goal <text> [--json]`.

Do not implement:

- tools, shell, file, git, HTTP, apply-patch.
- project instruction discovery.
- skill activation.
- hooks, automations, MCP runtime.
- subagents or swarm.
- workspace restore/revert.
- GUI live-provider path.
