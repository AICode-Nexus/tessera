# v0.7 Apply-Patch Executor Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking. Do not implement executor runtime before the design commit lands and the user explicitly approves starting the implementation chunks.

**Goal:** Add Tessera's first real apply-patch executor in conservative v0.7 slices, moving from metadata-only preflight/dry-run readiness to a trace-backed, worktree-first, single-file text patch execution path.

**Architecture:** Core owns executor orchestration. The executor only handles a preflight record that is explicitly executor-ready, writes only inside a caller-supplied isolated mutation root, and records first-class execution metadata. CLI, TUI, GUI, runtime API, and future app-server surfaces remain clients/projections or explicit intent sources; they do not own patch application.

**Tech Stack:** Rust workspace (`protocol`, `core`, `client`, `gui-bindings` when projection changes), JSONL trace metadata, serde/ts-rs DTOs, tempdir-based filesystem tests, TDD contract tests, Markdown docs.
