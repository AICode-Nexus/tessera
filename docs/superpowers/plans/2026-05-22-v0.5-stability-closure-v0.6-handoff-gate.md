# v0.5 Stability Closure And v0.6 Handoff Gate Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close v0.5 as foundation-stable, explicitly move runtime-complete gaps to future gates, and start v0.6 with a provider-neutral structured handoff and reviewer gate contract.

**Architecture:** Treat v0.5 closure as roadmap governance: no new runtime powers are claimed, and every staged gap gets a named future gate. Add v0.6 as trace/protocol/client foundation first, so CLI, TUI, GUI, replay, and future runtime API can inspect handoffs and reviewer decisions without creating a second execution system. Preserve the existing rule that core owns lifecycle and event routing; this slice does not execute tools, spawn subagents, start a daemon/app-server listener, mutate files, run hooks, or restore workspaces.

**Tech Stack:** Markdown docs, Rust `serde` protocol DTOs, trace-backed `RuntimeReader`/client projection if implementation proceeds, generated TypeScript bindings, `cargo fmt`, `cargo clippy`, `cargo test`, `git diff --check`.

---

## Scope

Implement this batch in three conservative layers:

- Document v0.5 as **Foundation stable** rather than runtime-complete.
- Define v0.6 structured handoff and reviewer gate semantics before any persistent sub-agent runtime.
- Add only provider-neutral protocol/projection foundations for handoff/reviewer events if the docs gate lands cleanly.

Do not implement:

- Tool execution, shell/file/git execution, apply-patch tools, or automatic model shell commands.
- Persistent sub-agent runtime, child process/session scheduling, background fan-out, swarm scheduling, or recursive agent execution.
- MCP runtime, hook runtime, automation runtime, app-server listener, daemon process, provider socket freezing, or runtime ownership transfer after process exit.
- Project instruction or skill default/global loading, Claude imports, executable skills, skill install/update/delete, or model-driven skill reference selection.
- Real checkpoint restore, workspace restore/revert, GUI Git mutation, or non-reviewed file mutation.
- Long-term memory runtime or learning apply path.
