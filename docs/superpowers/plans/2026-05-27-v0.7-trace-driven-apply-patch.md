# v0.7 Trace-Driven Apply-Patch Workflow Automation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a trace-driven `tessera apply-patch --from-trace <trace_id>` mode that resolves a reviewed coding workflow bundle from trace metadata and invokes the existing narrow apply-patch gate/executor.

**Architecture:** Keep execution core-owned and shared. Add a non-mutating trace resolver that turns existing protocol events into a typed apply envelope. CLI reads trace/artifact storage, resolves selectors, loads exactly one patch body source, then calls the same gate/executor append path used by the explicit CLI. No worktree lifecycle, tests, checkpoint restore, Git mutation, GUI/TUI/app-server mutation controls, shell commands or provider tool execution.

**Tech Stack:** Rust workspace (`cli`, `core`, `protocol`, `storage`), Clap, serde JSON output, JSONL trace store, artifact body storage, tempdir-based contract tests, TDD, Markdown docs.
