# v0.7 Read-Only Workflow Surfaces Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the currently permitted v0.7 gaps for trace-backed worktree lifecycle visibility and read-only coding workflow surfaces without adding blocked runtime capabilities.

**Architecture:** Keep `core` and `client` as trace/projection owners, with CLI/TUI/GUI consuming read-only summaries. Worktree changes must stay limited to lifecycle trace inspection and diagnostics; GUI/TUI additions must render existing `ClientSnapshot` metadata without adding mutation controls, provider calls, storage internals, test execution, checkpoint restore, Git mutation, hooks, automations, swarm, or learning.

**Tech Stack:** Rust workspace (`tessera-core`, `tessera-client`, `tessera-cli`, `tessera-tui`, `tessera-gui-bindings`) plus React/TypeScript Tauri GUI (`apps/gui-tauri`).

---

## Context And Gates

- v0.7 currently has metadata-only coding workflow contracts, narrow isolated apply-patch execution, trace-driven `--auto-worktree`, and conservative `tessera worktree cleanup`.
- Current allowed work is read-only projection, trace inspection, diagnostics, and UI display over existing metadata.
- Do not add test runner execution, checkpoint restore/revert, branch/stage/commit/push/PR Git mutation, GUI/TUI/app-server mutation controls, hooks, automations, swarm, learning, MCP/tool runtime, provider execution, file contents, patch bodies, stdout/stderr bodies, absolute source/worktree paths in trace, or secrets in trace/UI summaries.
- Update `docs/version-plan.md`, `docs/global-plan.md`, `docs/coding-agent-direction.md`, `docs/protocol-v0.md`, `docs/trace-schema-v0.md`, and `CHANGELOG.md` only when the implemented slice changes their contract or checklist status.

## File Structure

- Modify `crates/client/src/lib.rs` to add UI-neutral worktree lifecycle projection types and status summaries from live events and replayed trace records.
- Modify `crates/client/tests/client_contract.rs` to cover live and replayed worktree lifecycle projection.
- Modify `crates/core/src/lib.rs` to add `RuntimeReader::list_worktree_lifecycles` and a small `RuntimeWorktreeLifecycleSummary` projection from trace records.
- Modify `crates/core/tests/conversation_engine_contract.rs` or create `crates/core/tests/worktree_lifecycle_reader_contract.rs` for reader coverage.
- Modify `crates/cli/src/lib.rs`, `crates/cli/src/main.rs`, and `crates/cli/tests/cli_contract.rs` to add read-only `tessera worktree list --trace <trace_id> [--json]` and improve cleanup evidence diagnostics.
- Modify `crates/gui-bindings/tests/bindings_contract.rs` and regenerate `apps/gui-tauri/src/generated/bindings.ts` when new client DTOs are added.
- Modify `crates/tui/src/lib.rs` and `crates/tui/tests/tui_contract.rs` to include compact workflow/worktree summaries in the existing status rendering path.
- Modify `apps/gui-tauri/src/types.ts`, `apps/gui-tauri/src/view-model.ts`, `apps/gui-tauri/src/view-model.test.ts`, `apps/gui-tauri/src/App.tsx`, `apps/gui-tauri/src/App.smoke.test.tsx`, and `apps/gui-tauri/src/styles.css` to add read-only coding workflow/worktree panels fed only by `ClientSnapshot`.
- Modify docs and changelog only after code is verified.
