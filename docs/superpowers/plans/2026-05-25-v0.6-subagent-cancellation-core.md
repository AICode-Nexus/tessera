# v0.6 Subagent Cancellation Core Helper Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a non-executing core helper for sub-agent cancellation cascade records.

**Architecture:** Reuse existing protocol DTOs and client projection. Extend `SubagentRuntimeCoordinator` with one request type, validation, a record builder, and an event helper while keeping child cancellation, provider calls, scheduler work, storage writes, tools, workspace mutation, and UI actions out of scope.

**Tech Stack:** Rust, `tessera-core`, `tessera-protocol`, Markdown docs, `cargo fmt`, `cargo clippy`, `cargo test`, `git diff --check`.

---

## Scope

Implement only:

- `SubagentCancellationRequest`.
- Core validation and event helpers for the existing cancellation protocol record.
- Targeted core tests.
- Roadmap/docs/changelog status updates.

Do not implement:

- Child-agent scheduling or execution.
- Provider-backed child cancellation.
- Provider socket freezing.
- Automatic cancellation propagation.
- Storage writes from the helper.
- Tool execution.
- GUI commands.
- Hooks, automations, MCP runtime, app-server listener, swarm, workspace mutation, memory, or learning runtime.

- [x] **Step 2: Implement request type and helpers**

Add:

```rust
pub struct SubagentCancellationRequest {
    pub session: SubagentSessionDescriptor,
    pub source_task_id: TaskId,
    pub cascade: SubagentCancellationCascade,
    pub reason: String,
}
```

Add methods on `SubagentRuntimeCoordinator`:

- `record_cancellation(request) -> Result<SubagentCancellationRecord, SubagentRuntimeError>`
- `cancellation_event(request) -> Result<RunEvent, SubagentRuntimeError>`

Validation:

- `reason` must be non-empty after trimming.
- `source_task_id` must equal the parent task id or the current child task id.
- `CancelChild` requires `session.child_task_id`.
- `ObserveOnly` and `QueueCancellation` are metadata-only and allowed for linked source task ids.
