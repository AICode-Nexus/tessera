# v0.7 Apply-Patch Executor Gate Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a non-mutating apply-patch preflight and dry-run gate before Tessera implements any file-writing apply-patch executor.

**Architecture:** Keep execution blocked. Add core-owned validation that binds mutation request, patch proposal, checkpoint, reviewer, policy, sandbox, worktree and artifact evidence into a readiness record. Add patch artifact dry-run summaries without opening or writing workspace files, then project readiness to clients as read-only metadata.

**Tech Stack:** Rust workspace (`protocol`, `core`, `client`, `gui-bindings` if needed), JSONL trace metadata, serde/ts-rs DTOs, TDD contract tests, Markdown docs.

- sandbox profile label present;
- worktree-first mode with an isolated root label.
