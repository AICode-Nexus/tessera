# v0.7 Read-Only Diff/Review/Approval Inspection Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add read-only diff/review/approval inspection surfaces for existing
v0.7 coding workflow evidence without adding mutation or execution behavior.

**Architecture:** Add a safe inspection projection in `tessera-client` from
existing workflow/reviewer/approval state, then consume that projection from
CLI, TUI and GUI. The projection must contain only generated ordinal refs,
counts, statuses and bounded artifact-ref counts; raw workflow records remain
available internally but are not rendered by the new inspection surfaces.

**Tech Stack:** Rust workspace (`protocol`, `client`, `cli`, `tui`,
`gui-bindings`), TypeScript React/Vitest GUI, JSONL trace replay through
`ClientSnapshot`.
