# v0.7 Test Evidence Summary Contract Design

## Goal

Add a metadata-only test evidence summary contract for v0.7 coding-agent workflows.

The summary must let CLI/TUI/GUI/replay surfaces answer "what test evidence exists for this workflow?" without running tests, reading stdout/stderr bodies, restoring checkpoints, mutating Git, or trusting UI-local state.

## Current State

Tessera already has:

- `TestPlanRecord` for proposed command labels, affected paths, and required artifact kinds.
- `TestRunRecord` for one recorded test run, status, exit code, duration, output artifact ids, diagnostics, and redaction status.
- `ReviewBundle` for linking patch ids, test run ids, evidence refs, and reviewer-gate summary text.
- `ClientCodingWorkflow` projection for test plans and test runs.

What is missing is a first-class summary object that can aggregate multiple test runs into a reviewable evidence contract without requiring every client to recompute counts, inspect artifact handles, or infer readiness from raw run records.

## Contract Shape

Add a provider-neutral `TestEvidenceSummaryRecord` and `test_evidence_summary_recorded` trace event.

Required fields:

- `summary_id`
- `workflow_id`
- `task_id`
- `test_plan_ids`
- `test_run_ids`
- `status`
- `total_runs`
- `passed_runs`
- `failed_runs`
- `cancelled_runs`
- `error_runs`
- `required_artifact_kinds`
- `artifact_refs`
- `diagnostics`
- `redaction_status`
- `summary`
- `execution_blocked`

`status` is an aggregate status, not a runner status:

- `passed`: at least one run exists and all recorded runs passed.
- `failed`: at least one recorded run failed.
- `cancelled`: no failed runs exist and at least one run was cancelled.
- `error`: no failed/cancelled runs exist and at least one run errored.
- `incomplete`: plans exist but no complete test-run evidence exists yet.

`execution_blocked` must be `true` in this v0.7 slice. A summary records evidence only; it must not start tests or imply future test execution is available.

## Validation Rules

Core may construct the event only when:

- `summary` is non-empty;
- `total_runs == passed_runs + failed_runs + cancelled_runs + error_runs`;
- at least one `test_plan_id`, `test_run_id`, `artifact_ref`, or diagnostic evidence ref exists;
- `execution_blocked == true`;
- `redaction_status` is `redacted` if any referenced run or diagnostic has redacted evidence.

The event must not contain:

- command bodies beyond stable command labels already present in `TestRunRecord`;
- stdout/stderr bodies;
- file contents;
- absolute source or worktree paths;
- process ids, shell execution handles, checkpoint restore commands, Git commands, API keys, cookies, authorization headers, provider-private responses, or hidden reasoning.

## Projection Rules

`ClientCodingWorkflow` should store `test_evidence_summaries` beside test plans/runs and review bundles.

`ClientStatus.coding_workflow_summary` should include the number of test evidence summaries so compact UI surfaces can show that a workflow has aggregated evidence.

The projection is still read-only. GUI bindings may expose the new DTO, but no GUI/TUI control may run tests from it.

## Non-Goals

- Real test runner execution.
- Shell command execution.
- Reconstructing stdout/stderr from artifact storage.
- Checkpoint creation or restore.
- Branch, stage, commit, push, pull request, or CI mutation.
- GUI-owned test execution state.
