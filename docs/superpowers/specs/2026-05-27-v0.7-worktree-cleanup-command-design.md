# v0.7 Worktree Cleanup Command Design

## Goal

Add a conservative operator-triggered cleanup command for detached worktrees created by `tessera apply-patch --from-trace --auto-worktree`.

The command must let an operator remove a retained generated worktree after inspection without expanding Tessera into general Git automation.

## Command Shape

```bash
tessera worktree cleanup \
  --from-trace <trace_id> \
  --worktree-id <workspace_worktree_id> \
  --worktree-path <local_path> \
  [--source-root <repo_path>] \
  [--dry-run] \
  [--json]
```

`--worktree-path` is required because trace records intentionally do not store absolute local worktree paths. `--source-root` defaults to the current Git checkout when omitted.

## Required Evidence

Cleanup is allowed only when trace history proves all of the following:

- the requested worktree id exists in `workspace_worktree_lifecycle_recorded` records;
- the same worktree id has a `created` lifecycle record;
- the latest lifecycle state is `retained`;
- the record root label is a generated non-primary `worktree:*` label;
- the supplied local path leaf matches the deterministic leaf derived from trace-safe lifecycle metadata.

If the worktree was never retained, has already recorded `cleanup_completed`, or the supplied path does not match the lifecycle metadata, the command fails before running Git. If Git reports that the retained worktree still contains local changes, the command records `cleanup_failed` and exits non-zero rather than force-removing it.

## Execution Boundary

The command may run only:

```bash
git worktree remove <worktree-path>
```

through the existing fixed Git worktree runner. It must not pass `--force`, run tests, restore checkpoints, stage, commit, push, open PRs, switch branches, run provider tools, execute shell commands from the model, or mutate the primary checkout.

Non-dry cleanup appends path-redacted lifecycle records:

1. `cleanup_started`
2. `cleanup_completed` or `cleanup_failed`

Dry-run performs trace/path validation only and must not append lifecycle records or remove files.

## Trace Rules

Trace records must continue to exclude:

- absolute source checkout paths;
- absolute generated worktree paths;
- Git command strings;
- stdout/stderr bodies;
- file contents;
- secrets or provider-private handles.

The CLI may print the local worktree path in operator output, just like `--auto-worktree` creation does.

## Non-Goals

- General `git worktree prune`.
- Force removal of dirty worktrees.
- Branch/stage/commit/push/PR Git automation.
- Test runner integration.
- Checkpoint restore or workspace rollback.
- GUI/TUI mutation controls.
