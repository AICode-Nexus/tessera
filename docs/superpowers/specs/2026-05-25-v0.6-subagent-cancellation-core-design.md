# v0.6 Subagent Cancellation Core Helper Design

## Goal

Add a core-owned, non-executing helper for sub-agent cancellation cascade metadata. The helper should validate and construct the existing provider-neutral `SubagentCancellationRecord` and `RunEvent::SubagentCancellationRecorded` without cancelling child runtime work, calling providers, executing tools, writing storage, driving UI actions, or widening any blocked v0.6 runtime gate.

## Context

The v0.6 foundation already defines and projects:

- `SubagentCancellationCascade`
- `SubagentCancellationRecord`
- `RunEvent::SubagentCancellationRecorded`
- Client/GUI cancellation cascade projections

`SubagentRuntimeCoordinator` now owns deterministic helpers for runtime decisions, transcript artifact lifecycle metadata, approval-forwarding metadata, and inactive-child policy metadata. Cancellation cascade metadata should follow the same pattern so future runtime-capable slices do not invent cancellation validation in CLI, TUI, GUI, provider, storage, or app-server code.

## Approaches Considered

### Recommended: Extend `SubagentRuntimeCoordinator`

Add one request type and two helper methods:

- `SubagentCancellationRequest`
- `record_cancellation`
- `cancellation_event`

This keeps cancellation metadata construction in core, uses existing protocol DTOs, and stays testable without child execution.

### Alternative: Let callers construct records directly

This is the smallest change, but it weakens the runtime boundary by allowing each future entry point to decide which task ids and cascade modes are valid.

### Alternative: Implement executable child cancellation

This is out of scope. Real child cancellation needs persistent child lifecycle, scheduler coordination, task ownership, reattach behavior, provider-backed child execution, and durable transcript handling before it can be made safe.

## Design

The slice adds a request type:

```rust
pub struct SubagentCancellationRequest {
    pub session: SubagentSessionDescriptor,
    pub source_task_id: TaskId,
    pub cascade: SubagentCancellationCascade,
    pub reason: String,
}
```

The helper returns either a `SubagentCancellationRecord` or a `RunEvent::SubagentCancellationRecorded`.

Validation is intentionally narrow:

- `reason` must be non-empty after trimming.
- `source_task_id` must match the parent task id or the current child task id when a child task id is present.
- `CancelChild` requires a child task id.
- `ObserveOnly` records cancellation metadata without runtime cancellation.
- `QueueCancellation` records deferred intent metadata without runtime cancellation.

The returned record preserves the source task id, cascade mode, reason, session id, and parent task id. The helper does not mutate the session descriptor.

## Data Flow

1. A future runtime component or test creates a `SubagentSessionDescriptor`.
2. The caller passes it to `SubagentRuntimeCoordinator` with a cancellation request.
3. The coordinator validates the linked source task and cascade mode.
4. The coordinator returns a provider-neutral `SubagentCancellationRecord`.
5. The event helper wraps the record in the existing `RunEvent` variant for ordinary trace projection.

## Testing

Use TDD in `crates/core/tests/subagent_runtime_contract.rs`.

Tests should prove:

- `CancelChild` requires a child task id.
- `CancelChild` preserves source task id, cascade mode, and reason.
- unrelated source task ids are rejected.
- `ObserveOnly` emits metadata-only events.
- `QueueCancellation` preserves deferred cancellation reason.
- empty reasons are rejected.

Targeted verification:

```bash
PATH="$HOME/.cargo/bin:$PATH" cargo test -p tessera-core subagent_cancellation_core
PATH="$HOME/.cargo/bin:$PATH" cargo test -p tessera-core --test subagent_runtime_contract
```

Final verification remains the repository gate:

```bash

PATH="$HOME/.cargo/bin:$PATH" cargo test --workspace
git diff --check
```

## Boundaries

This slice must not implement:

- child-agent scheduling or execution;
- provider-backed child cancellation;
- provider socket freezing;
- automatic task cancellation propagation;
- transcript body storage or retention;
- storage writes from the helper;
- tool execution;
- workspace mutation;
- hooks, automations, app-server listener, MCP runtime, swarm, memory, or learning runtime.
