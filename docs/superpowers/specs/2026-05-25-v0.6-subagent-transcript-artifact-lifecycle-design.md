# v0.6 Subagent Transcript Artifact Lifecycle Design

日期：2026-05-25

## 1. Purpose

This design defines the next v0.6 foundation slice after sub-agent runtime ownership metadata. It gives Tessera a replayable lifecycle for sub-agent transcript artifact handles before any persistent child-agent execution is allowed.

The goal is not to run child providers, store full child transcript contents, or schedule sub-agents. The goal is to make transcript artifact publication explicit, trace-backed, parent/child-linked, and safe for CLI, TUI, GUI, replay, and future runtime API projection.

## 2. Current Baseline

Already present:

- Provider-neutral handoff and reviewer gate events.
- Provider-neutral sub-agent session metadata events with parent/child task linkage, caps, transcript artifact handles, approval forwarding metadata, and inactive-child policy metadata.
- Provider-neutral sub-agent runtime ownership events:
  - `subagent_runtime_decision_recorded`
  - `subagent_transcript_artifact_recorded`
  - `subagent_approval_forwarding_recorded`
  - `subagent_inactive_policy_recorded`
  - `subagent_cancellation_recorded`
- A non-executing `SubagentRuntimeCoordinator` in `tessera-core` that validates caps/reviewer/transcript metadata and returns decisions.
- Read-only `tessera-client` and GUI binding projection for sub-agent session and runtime ownership metadata.
- Generic `artifact_created` events and artifact handle projection.

Missing:

- No lifecycle state says a sub-agent transcript artifact handle was reserved, published, sealed, or abandoned.
- No core helper validates transcript artifact event ranges against a session and parent/child task linkage.
- No deterministic rule says completion can only refer to a sealed or explicitly published transcript artifact handle.
- No trace-backed lifecycle lets future child execution publish transcript artifacts without leaking transcript content into parent context.

## 3. Non-Goals

This slice must not implement:

- Provider-backed child-agent execution.
- Concurrent fan-out or swarm scheduling.
- Tool execution, shell/file/git execution, apply-patch, or workspace mutation.
- Storage of full transcript text in protocol events, trace metadata, tests, or GUI bindings.
- App-server listener, daemon, MCP runtime, hook runtime, or automation runtime.
- Automatic approval forwarding.
- Transcript summarization by a model.
- Parent context ingestion of child transcript content.

## 4. Design Options

### Option A: Keep Using `subagent_transcript_artifact_recorded`

The existing runtime ownership event continues to be the only transcript artifact signal.

Pros:

- No new protocol events.
- Small implementation surface.

Cons:

- Cannot distinguish reservation, publication, sealing, and abandonment.
- Future child runtime has no replayable artifact lifecycle.
- Completion validation remains weak.

Rejected as too vague for the next runtime gate.

### Option B: Add A Full Transcript Store Now

Create storage for transcript bodies and connect it to child runs.

Pros:

- Moves closer to real runtime behavior.
- Gives a natural place for child transcript content.

Cons:

- Pulls in content retention, redaction, storage policy, summarization, and parent context ingestion too early.
- Risks leaking full child transcript content into trace or UI.
- Tempts provider-backed child execution before lifecycle metadata is stable.

Deferred.

### Option C: Trace-Backed Transcript Artifact Lifecycle First

Add provider-neutral lifecycle metadata for transcript artifact handles only. Core can reserve, publish, seal, or abandon transcript artifact handles and validate linkage. The lifecycle events reference artifact IDs and event ranges, never transcript bodies.

Pros:

- Preserves Tessera's trace-first architecture.
- Keeps parent/child linkage replayable without full transcript content.
- Gives future child execution a safe artifact contract.
- Lets client/GUI project lifecycle state read-only.

Cons:

- Does not store real transcript content.
- Requires another metadata layer before child runtime work.

Recommended.

## 5. Recommended Contract

Add a transcript artifact lifecycle contract with these states:

- `reserved`: a transcript artifact handle is allocated for a sub-agent session before child execution.
- `published`: a bounded event range has been associated with the transcript artifact handle.
- `sealed`: no further event ranges should be associated with the handle.
- `abandoned`: the handle is no longer usable because the session failed, was cancelled, or did not produce transcript evidence.

The lifecycle is metadata only. Event payloads may include:

- `session_id`
- `parent_task_id`
- optional `child_task_id`
- `artifact_id`
- `status`
- optional `event_range`
- optional `summary_label`
- `reason`

Event payloads must not include full transcript text, provider-private raw responses, hidden reasoning, tool output, file contents, shell output, secrets, authorization headers, cookies, workspace diffs, or filesystem handles.

## 6. Protocol Shape

Add provider-neutral DTOs:

```rust
pub enum SubagentTranscriptArtifactStatus {
    Reserved,
    Published,
    Sealed,
    Abandoned,
}

pub struct SubagentTranscriptArtifactLifecycleRecord {
    pub session_id: SubagentSessionId,
    pub parent_task_id: TaskId,
    pub child_task_id: Option<TaskId>,
    pub artifact_id: ArtifactId,
    pub status: SubagentTranscriptArtifactStatus,
    pub event_range: Option<EventRange>,
    pub summary_label: Option<String>,
    pub reason: String,
}
```

Add event:

```rust
RunEvent::SubagentTranscriptArtifactLifecycleRecorded {
    lifecycle: SubagentTranscriptArtifactLifecycleRecord,
}
```

Stable event kind:

```text
subagent_transcript_artifact_lifecycle_recorded
```

The existing `subagent_transcript_artifact_recorded` event remains as runtime ownership publication metadata. The new lifecycle event provides state transitions around that artifact handle.

## 7. Core Shape

Add a non-executing core helper, likely in `crates/core/src/subagent_runtime.rs` unless it grows enough to justify `subagent_transcript.rs`.

The helper should:

- Accept a `SubagentSessionDescriptor`, artifact id, lifecycle status, optional event range, optional summary label, and reason.
- Validate that `Published` and `Sealed` records have an event range.
- Validate that `Reserved` and `Abandoned` records can omit event range.
- Validate that event ranges are non-empty when present.
- Emit `RunEvent::SubagentTranscriptArtifactLifecycleRecorded`.
- Optionally update `SubagentRuntimeCoordinator::plan_completion` so completion requires a transcript artifact id and can be paired with a sealed/published lifecycle record in tests.

It must not:

- Call providers.
- Spawn tasks.
- Execute tools.
- Read or write transcript body files.
- Reach into storage internals.
- Schedule child sessions.

## 8. Client And GUI Projection

Extend read-only projection with `ClientSubagentTranscriptLifecycle` records and a short status summary.

Projection rules:

- Live events and replayed trace records produce identical client state.
- The artifact id is projected as `ArtifactKind::AgentTranscript`.
- `referenced_by_event_kinds` includes `subagent_transcript_artifact_lifecycle_recorded`.
- GUI bindings export protocol and client DTOs.
- GUI commands remain unchanged; no transcript action command is added.

## 10. Testing Strategy

Use TDD.

Protocol tests:

- Lifecycle DTO serializes stable snake_case statuses.
- Event kind is `subagent_transcript_artifact_lifecycle_recorded`.
- Payload redaction test rejects transcript/body/tool/secret/workspace-diff fields.

Core tests:

- Reserved lifecycle can omit event range.
- Published lifecycle rejects missing or empty event range.
- Sealed lifecycle emits a lifecycle event and remains non-executing.
- Abandoned lifecycle carries reason metadata without transcript content.

Client tests:

- Live lifecycle events project to `ClientSnapshot`.
- Replayed trace lifecycle records project the same state.
- Artifact handle is projected as `AgentTranscript`.
- Summary counts reserved/published/sealed/abandoned.

GUI binding tests:

- Generated bindings include lifecycle DTOs and event kind.
- Generated bindings still exclude scheduler, child execution, provider, file mutation, and transcript body commands.

Verification:

```bash
PATH="$HOME/.cargo/bin:$PATH" cargo fmt --all -- --check
PATH="$HOME/.cargo/bin:$PATH" cargo clippy --workspace --all-targets -- -D warnings
PATH="$HOME/.cargo/bin:$PATH" cargo test --workspace
git diff --check
```

## 11. Open Constraints

- This design intentionally does not decide where real transcript bodies are stored.
- This design intentionally does not decide retention, compaction, or redaction policy for transcript bodies.
- Future runtime work must add those policies before provider-backed child execution writes real artifacts.
