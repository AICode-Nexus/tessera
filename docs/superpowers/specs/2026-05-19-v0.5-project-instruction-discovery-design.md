# v0.5 Project Instruction Discovery Design

Date: 2026-05-19

## 1. Purpose

This design defines Tessera's first project instruction discovery foundation. It lets the runtime find bounded, traceable, redacted project instruction sources before a future coding-agent run uses them as context.

The goal is intentionally narrower than full instruction ingestion:

- discover project-local instruction files from a workspace root to a target directory.
- prefer `AGENTS.md` first.
- support `CLAUDE.md` as a fallback compatibility source.
- produce a loaded-source report with precedence, byte limits, hashes, redaction state and trace references.
- make CLI inspection possible before instruction content is injected into provider prompts.

This slice must not execute hooks, expand imports, read user-home global instructions, activate skills, execute tools, mutate files, start MCP, or create a second instruction loader in CLI/TUI/GUI.

## 2. External Direction

Tessera should align with common coding-agent expectations without cloning any single product:

- Codex-style `AGENTS.md` is the primary project instruction file name and can appear at multiple directory levels.
- Claude Code-style `CLAUDE.md` compatibility matters, but it should be treated as fallback input in this first Tessera slice.
- Both file families are high-risk context inputs: they can alter model behavior, contain secrets, be stale, or live outside the intended workspace if discovery is sloppy.

Therefore Tessera should treat instruction files as auditable context sources, not invisible prompt text.

## 3. Current Baseline

Already present:

- `ContextReference`, `ContextSource`, `ContextPlacement` and `ContextWorkbench`.
- `AgentLoop` with no-tool `AgentRunRequest`, trace-backed run/step events and machine-readable summaries.
- `RuntimeReader` task projection and JSONL trace storage.
- `docs/crate-boundaries.md` already defines an `instruction_loader` boundary.
- `docs/global-plan.md` gates project instruction ingestion on precedence rules, byte limits, source reporting, redaction and trace references.

Missing:

- No protocol type for instruction sources.
- No trace event records discovered instruction sources.
- No core discovery planner can safely walk root-to-target instruction files.
- No byte-limit, UTF-8, hash or redaction contract exists for instruction content.
- No CLI command can inspect which instructions would load.
- `tessera agent run` has no instruction-source report and does not pass instruction context to provider messages.

## 4. Non-Goals

This slice must not implement:

- user-global instruction discovery from `$HOME` or config directories.
- `CLAUDE.md` import expansion such as `@path`.
- `.claude/` recursive rules.
- `AGENTS.override.md`, package-manager-specific rules, editor rules, or MCP resource loading.
- tool execution, shell execution, file mutation, git mutation or apply-patch.
- skill runtime or `SKILL.md` activation.
- hook runtime or automation runtime.
- background task ownership or provider socket reattach.
- prompt compaction, semantic summarization or long-term memory writes.

## 5. Approaches Considered

### Approach A: Metadata-Only Discovery Command

Add a core planner and `tessera instructions inspect`, but do not wire results into `AgentLoop`.

Pros:

- Safest first step.
- Easy to review and test.
- No prompt behavior changes.

Cons:

- Does not exercise provider-facing instruction placement.
- Leaves `agent run` less useful for coding-agent workflows.

### Approach B: Discovery Plus Opt-In Agent Context

Add protocol/core/CLI inspection, then allow `tessera agent run --instructions --workspace <path>` to prepend a bounded system message generated by core.

Pros:

- Creates the complete runtime path while avoiding surprising default behavior.
- Keeps source reports traceable.
- Lets scripts and tests choose instruction loading explicitly.

Cons:

- Adds CLI surface area.
- Requires careful JSON/text output updates.

### Approach C: Default-On Full Project Instruction Loading

Make `tessera agent run` always discover instructions from the current directory.

Pros:

- Closest to expected coding-agent UX.
- Less to type.

Cons:

- Surprising for existing scripts.
- Harder to reason about test output.
- Reads project files without an explicit CLI signal.

Recommended path: Approach B. Use explicit opt-in loading first. Later, once source reports and user-facing docs are stable, Tessera can decide whether a coding-agent command should default to instruction loading.

## 6. Discovery Semantics

Inputs:

- `workspace_root`: explicit path or current working directory.
- `target_dir`: explicit path or `workspace_root`.
- `primary_names`: initially `["AGENTS.md"]`.
- `fallback_names`: initially `["CLAUDE.md"]`.
- per-source byte limit: default `16 KiB`.
- combined loaded-byte limit: default `48 KiB`.
- placement: default `stable_prefix`.

Path rules:

- Canonicalize `workspace_root`.
- Canonicalize `target_dir` and require it to be inside `workspace_root`.
- Walk ancestors from `workspace_root` to `target_dir`, inclusive.
- At each directory, choose at most one source:
  - first existing `AGENTS.md`.
  - if no `AGENTS.md`, first existing `CLAUDE.md`.
- Do not follow symlinks.
- Only regular UTF-8 files are loadable.
- Unreadable, non-UTF-8, oversized or symlink candidates enter the source report with warnings, but their content is not used.

Precedence:

- Broad instructions load before specific instructions.
- More specific directories appear later in the generated system message, so they can override earlier guidance.
- `AGENTS.md` wins over `CLAUDE.md` in the same directory.
- `CLAUDE.md` fallback is compatibility, not a promise to implement Claude-specific imports or memory behavior.

## 7. Protocol Additions

Add conservative provider-neutral metadata:

```rust
pub enum InstructionSourceKind {
    AgentsMd,
    ClaudeMd,
}

pub enum InstructionLoadStatus {
    Loaded,
    SkippedLowerPrecedence,
    SkippedSymlink,
    SkippedOutsideWorkspace,
    SkippedNonUtf8,
    SkippedTooLarge,
    ReadFailed,
}

pub enum InstructionRedactionStatus {
    Clean,
    Redacted,
}

pub struct InstructionSource {
    pub source_id: ContextId,
    pub kind: InstructionSourceKind,
    pub path: String,
    pub relative_path: String,
    pub precedence: u32,
    pub placement: ContextPlacement,
    pub status: InstructionLoadStatus,
    pub original_bytes: u64,
    pub loaded_bytes: u64,
    pub sha256: Option<String>,
    pub redaction_status: InstructionRedactionStatus,
    pub warnings: Vec<String>,
}
```

Add a trace event:

```rust
RunEvent::InstructionsDiscovered {
    task_id: TaskId,
    sources: Vec<InstructionSource>,
}
```

Trace payload must never contain instruction file content. It records source metadata only.

## 8. Core Additions

Add a focused instruction discovery module or section in `tessera-core`:

- `InstructionDiscoveryOptions`
- `InstructionDiscoveryReport`
- `LoadedInstruction`
- `LoadedInstructionSet`
- `InstructionDiscoveryPlanner`

The report should include:

- selected source metadata for trace and CLI.
- skipped source metadata for inspection.
- redacted loaded text for provider prompt construction.
- `ContextReference` handles for loaded sources.
- warnings.

The planner owns all filesystem reads for project instructions. CLI/TUI/GUI must not independently read and merge instruction files.

## 9. Redaction And Hashing

Redaction is intentionally simple and conservative in v0.5:

- Redact full lines containing obvious secret markers such as `api_key`, `apikey`, `token`, `secret`, `password`, `authorization`, `bearer`, `cookie` and `.env`.
- Replace the line with `[REDACTED: possible secret]`.
- Keep byte counts and source metadata.
- Hash original bytes with SHA-256 before redaction if the file is loadable.
- Do not write original bytes to trace, logs, tests, JSON output or error messages.

This is not a comprehensive secret scanner. It is a guardrail so the first implementation is not recklessly piping obvious secrets into prompts.

## 10. Agent Integration

`AgentRunRequest` should accept an optional loaded instruction set.

When present:

- `AgentLoop` emits `instructions_discovered` after `user_message_recorded` and before `agent_run_started`.
- `AgentLoop` prepends a single system message to provider messages.
- The system message is generated by core from redacted source text, with source headers such as:

```text
Project instructions follow. More specific sources appear later and override earlier sources.

--- AGENTS.md: ./AGENTS.md ---
...

--- CLAUDE.md fallback: packages/foo/CLAUDE.md ---
...
```

The source headers are for model context only; trace still stores metadata, not content.

CLI should expose this as opt-in:

```bash
tessera agent run --provider mock --goal "summarize" --instructions --workspace .
tessera agent run --provider mock --goal "summarize" --instructions --workspace . --json
```

JSON output should include an `instruction_sources` summary. Text output should include a short source count and warning count.

## 11. CLI Inspection

Add:

```bash
tessera instructions inspect --workspace . --target-dir . --json
tessera instructions inspect --workspace .
```

Text output should be concise:

```text
instruction sources: 2 loaded, 1 skipped, 0 warnings
1. loaded AGENTS.md AGENTS.md 234 bytes clean
2. loaded AGENTS.md crates/core/AGENTS.md 812 bytes redacted
```

JSON output should return the full `InstructionDiscoveryReport` metadata but not raw instruction content.

## 12. Error Handling

Hard errors:

- workspace root does not exist.
- target dir does not exist.
- target dir is outside workspace root.
- combined byte budget is zero.
- per-source byte budget is zero.

Soft warnings:

- source file is unreadable.
- source file is symlink.
- source file is non-UTF-8.
- source file exceeds per-source limit.
- source skipped because another file in the same directory had higher precedence.
- unsupported `CLAUDE.md` import-like lines detected.

Soft warnings should not abort `instructions inspect` or `agent run --instructions` unless no usable instruction content remains and the caller explicitly asks for strict mode in a future slice.

## 13. Testing Strategy

Protocol tests:

- `instructions_discovered_event_records_sources_without_content`
- source enum serialization is snake_case and provider-neutral.

Core tests:

- root-to-target AGENTS discovery order.
- nested AGENTS overrides broad instructions by later placement.
- CLAUDE fallback loads only when AGENTS is absent in the same directory.
- CLAUDE is reported skipped when AGENTS exists in the same directory.
- symlink candidates are skipped.
- target outside workspace is rejected.
- non-UTF-8 candidates are skipped with warnings.
- per-source and combined byte limits are enforced at UTF-8 boundaries.
- obvious secret lines are redacted.
- `AgentLoop` emits `instructions_discovered` and prepends a system message only when instructions are provided.

CLI tests:

- `instructions inspect --json` reports sources without content.
- text output summarizes loaded/skipped/warnings.
- `agent run --instructions --workspace <path> --json` includes source metadata.
- unknown or outside workspace paths fail before trace mutation.

Docs/tests:

- Update README, crate README, protocol/trace docs, changelog and global plan.
- Full implementation gate remains `fmt`, `clippy`, `cargo test --workspace`, `git diff --check`.

## 14. Open Decisions Deferred

- Whether future coding-agent commands default instruction loading on.
- Whether user-global instructions should be supported.
- Whether Claude import expansion should be supported.
- Whether `AGENTS.override.md` should exist.
- Whether instruction content should be stored as encrypted artifacts or remain ephemeral.
- How instruction discovery interacts with skill activation and hook output.

## 15. Acceptance Criteria

- A user can inspect project instruction sources without running a provider.
- `AGENTS.md` is preferred over `CLAUDE.md`.
- Broad-to-specific precedence is deterministic and tested.
- Content is bounded, UTF-8-safe and redacted before provider use.
- Trace records source metadata and never records instruction content.
- CLI/TUI/GUI do not implement their own instruction file readers.
- No tools, skills, hooks, MCP, workspace mutation or background reattach are introduced.
