# v0.6 Subagent Owner Heartbeat Bridge Design

## Goal

Add core-owned, non-executing helpers that bridge sub-agent child task metadata to existing task owner heartbeat, lost-owner, and reattach events. The helpers should construct provider-neutral `RunEvent` values only; they must not start heartbeat loops, detect lost owners, persist trace records, resume providers, freeze provider sockets, schedule child agents, execute tools, mutate workspaces, or drive UI.

## Context

The current v0.6 foundation already has:

- sub-agent session metadata with parent/child task linkage;
- runtime ownership records for scheduler decisions, transcript lifecycle, approval forwarding, inactive policy, cancellation cascade, and task owner attach/detach metadata;
- existing protocol events for `task_owner_heartbeat`, `task_owner_lost`, and `task_reattach_recorded`;
- existing projection code in `RuntimeReader`, `tessera-client`, TUI, and GUI bindings for task owner metadata.

The missing sub-agent-specific bridge is deterministic construction and validation of child task heartbeat/lost/reattach metadata from a `SubagentSessionDescriptor`. Future runtime-capable slices can use the same core-owned validation before they add actual persistence and lifecycle automation.

## Approaches Considered

### Recommended: Extend `SubagentRuntimeCoordinator`

Add three request types and three event helpers:

- `SubagentTaskOwnerHeartbeatRequest`
- `SubagentTaskOwnerLostRequest`
- `SubagentTaskOwnerReattachRequest`
- `task_owner_heartbeat_event`
- `task_owner_lost_event`
- `task_owner_reattach_event`

This keeps child task ownership mapping in `core` and follows the existing coordinator pattern.

### Alternative: Let callers emit task owner events directly

This is smaller, but future CLI/TUI/GUI/provider/storage call sites would need to repeat child task id and reattach validation.

### Alternative: Add heartbeat loops and executable reattach now

This remains out of scope. Heartbeat scheduling, lost-owner detection, provider resume, socket freezing, app-server ownership transfer, and persistent child execution are still gated runtime work.

## Design

The helpers map a `SubagentSessionDescriptor` to the existing child task ownership event types:

```rust
pub struct SubagentTaskOwnerHeartbeatRequest {
    pub session: SubagentSessionDescriptor,
    pub lease_id: TaskOwnershipId,
    pub runtime_id: RuntimeInstanceId,
    pub heartbeat_at: Timestamp,
    pub expires_at: Timestamp,
    pub last_seq: u64,
}

pub struct SubagentTaskOwnerLostRequest {
    pub session: SubagentSessionDescriptor,
    pub lease_id: TaskOwnershipId,
    pub reason: String,
}

pub struct SubagentTaskOwnerReattachRequest {
    pub session: SubagentSessionDescriptor,
    pub mode: TaskReattachMode,
    pub previous_lease_id: Option<TaskOwnershipId>,
    pub new_lease_id: Option<TaskOwnershipId>,
    pub checkpoint_id: Option<TaskPauseCheckpointId>,
    pub since_seq: Option<u64>,
    pub reason: String,
}
```

Validation:

- all helpers require `child_task_id`;
- heartbeat rejects terminal sub-agent sessions, because completed/failed/cancelled sessions should not emit fresh heartbeat metadata;
- lost-owner and reattach require a non-empty reason;
- `ObserveExistingOwner` reattach requires `new_lease_id`;
- `ResumeFromCheckpoint` reattach requires `checkpoint_id`;
- `OwnerLost` reattach requires `previous_lease_id`;
- `TerminalProjection` reattach is allowed without a checkpoint or new lease because it is projection-only metadata.

The helpers return existing `RunEvent` variants and do not persist them.

## Data Flow

1. A future runtime component or test has a `SubagentSessionDescriptor` with `child_task_id`.
2. The caller creates a heartbeat, lost-owner, or reattach request.
3. `SubagentRuntimeCoordinator` validates child task linkage and mode-specific metadata.
4. The coordinator returns a standard task ownership event for the child task id.
5. Existing readers and clients can project the event without new protocol or UI shapes.

## Testing

Use TDD in `crates/core/tests/subagent_runtime_contract.rs`.

Tests should prove:

- heartbeat targets the child task id and preserves lease/runtime/timestamps/seq;
- heartbeat rejects terminal sub-agent sessions;
- lost-owner requires a child task id and non-empty reason;
- lost-owner event is metadata-only;
- observe-existing-owner reattach requires a new lease id;
- resume-from-checkpoint reattach requires a checkpoint id;
- terminal projection reattach targets the child task id and stays metadata-only.

## Boundaries

This slice must not implement:

- heartbeat loops;
- lost-owner detection;
- automatic reattach or provider resume;
- provider socket freezing;
- child-agent scheduling or provider execution;
- storage writes from the helper;
- automatic approval forwarding;
- inactive-child execution;
- cancellation execution;
- tool execution;
- workspace mutation;
- hooks, automations, app-server listener, MCP runtime, swarm, memory, or learning runtime.
